零知識證明(ZKP)與MERKLE TREE

2026-08-21
  • 零知識證明（ZKP）：證明「我知道答案」，但不透露答案內容。
  • Merkle Tree：利用單一 Root Hash，快速證明「某筆資料存在於指定集合中」。
  • 兩者結合：證明「我符合資格且屬於某合法集合」，同時隱匿個人身份與秘密。

1. 什麼是零知識證明？

以「密碼鎖」為例：

門內 (B)
┌───────────┐
│ 驗證者 B │
└─────┬─────┘
│
🔐 密碼鎖
│
┌─────┴─────┐
│ 證明者 A │
└───────────┘
門外 (A)

  • 傳統方式：A 直接告訴 B「密碼是 123456」（洩漏秘密）。
  • ZKP 方式：A 直接操作密碼鎖開門。B 見證門被開啟，即確信「A 知道密碼」，但全程未接觸到密碼本身。

核心三性質

  • 完備性（Completeness）：若陳述為真，誠實的證明者必能說服驗證者。
  • 健全性（Soundness）：若陳述為假，作弊者極不可能騙過驗證者。
  • 零知識性（Zero-Knowledge）：驗證者除了得知「陳述為真」外，獲取不到任何私密資訊。

2. 技術實作：SnarkJS Pipeline

基於 snarkjs 的標準流程：

  1. 定義電路：使用 Circom 編寫計算約束，編譯輸出 .r1cs（約束系統）與 .wasm（計算 Witness）。
  2. 計算 Witness：將私密輸入（secret、nullifier）傳入 .wasm 計算狀態值。
  3. Trusted Setup：生成 .zkey，包含 Proving Key 與 Verification Key。
  4. 生成證明：以 Groth16 演算法結合 Witness + R1CS + Proving Key，產生 proof.json 與公開訊號 public.json。
  5. 鏈上驗證：將證明傳送至 Verifier.sol 合約驗證。

proof.json 僅包含橢圓曲線的數學證明，完全不含原始私鑰或秘密輸入。

3. 什麼是 Merkle Tree？

Merkle Tree 為層級雜湊結構：

  1. Leaf（葉節點）：原始資料的 Hash 值。
  2. 中間節點：相鄰兩節點的 Hash 組合後再次 Hash，逐層向上收斂。
  3. Root：頂層唯一的 Hash 值，作為整份資料集的指紋。

只要任何底層資料變更，Root 即完全改變。

Merkle Proof（Merkle Path）

證明某資料存在於樹中，無需公開完整資料集，僅需提供該葉節點向上至 Root 的路徑雜湊（共 log_2 N 個節點），即可供他人比對 Root 是否相符。

4. ZKP + Merkle Tree 的結合應用

常見於匿名投票、隱私白名單、混幣協議等場景，用以解決：「證明自己屬於某集合，但不透露具體身份」。

  • Merkle Tree：將整份白名單壓縮為單一鏈上 Root。
  • ZKP 電路：證明「我擁有的 secret 所生成的 commitment 與 Merkle Path，可正確推導出公開的 Root」，且運算過程中的 secret、葉節點索引皆不公開。

證明者 (A) 持有：Secret + Merkle Path
│
▼
ZKP 電路生成 Proof
│
▼
驗證者 / 智能合約：驗證 Proof 與公開 Root
│
▼
